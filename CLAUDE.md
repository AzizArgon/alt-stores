# ALT STORES — дипломный проект «Разработка информационной системы мониторинга и стандартизации рынка компьютерной техники»
Название для людей — ALT STORES (`frontend/src/config/brand.js`); внутреннее имя в коде, папках, ключах и службах сервера — `pc_market`/`pcmarket`, не переименовывать. Стек, схема БД, подробности по фазам и замеры — в `docs/history.md`: читать только нужный раздел.
Дорожная карта и задания по фазам — `docs/roadmap.md`.

## Цель проекта
Цель: ALT STORES — единая база компьютерной техники Узбекистана. Система приводит прайсы любых магазинов к одному стандарту, чтобы покупатель мог честно сравнить предложения, а рынок стал прозрачнее. Для продавца это ещё и лёгкий учёт остатков по филиалам: он поддерживает наличие на витрине в актуальном состоянии и упрощает переход с Excel.
Приоритеты при конфликте интересов: 1) честность и качество базы; 2) покупатель; 3) удобство продавца.
Главные сцены: «хаос → порядок» (прайс или пост → чистые карточки), «поймали обман» (Anti-Fraud), «один товар — все магазины» (сравнение и мониторинг).
Не делаем: доставку и её отслеживание; оплату, кассу, фискальные чеки, налоги и бухгалтерию; перемещения между филиалами; учётные записи сотрудников филиалов; интеграцию с 1С; отчёты по выручке (только окно-заглушка); коды МХИК для чеков; раздел поставщиков; продажу от имени ALT STORES; конструктор ПК; мастеров.
Учёт остатков (12.1–12.3): режимы магазина «Только прайс» / «Учёт остатков»; остатки по филиалам видит только продавец, покупатель — «есть / нет» по филиалам; доступно = остаток − забронировано; все операции (приход, продажа, корректировка, резерв и выдача брони, снятие резерва) — в журнале движений; импорт/экспорт Excel; штрихкоды (USB-сканер, камера); одна учётная запись на магазин.
Фильтр для новых идей: укрепляет единую базу или использует её? Если нет — в «Идеи на потом».

## Ключевые решения
1. Стек: FastAPI + SQLAlchemy + SQLite (`create_all`, без Alembic: при смене схемы — `ALTER TABLE` или удалить `backend/database.db`), React (Vite) + Tailwind + react-i18next, JWT.
2. Стандартизация = эталонный товар + предложения магазинов (как Oson Apteka).
3. Сортировка предложений по умолчанию — «рекомендованные» (проверенный магазин, наличие, свежесть прайса), по цене — по выбору.
4. МХИК не генерирует ИИ: ИИ определяет категорию, код — из справочника `categories` (tasnif.soliq.uz).
5. Разбор прайса: кэш → правила → ИИ (Gemini, запасной Groq). Цену, артикул и наличие берёт код, не ИИ. «Предположения ИИ» в характеристиках не сохраняются.
6. Anti-Fraud: сначала правила кодом, ИИ — вторым слоем (уровень info). Флаг: тип, уровень info/warning/danger, ключ причины + параметры (тексты в `ru.json`), источник rule/ai. Формулировки мягкие; продавец может оспорить.
7. Импорт: загрузка → разбор → редактируемый предпросмотр → публикация. Повторная загрузка файла обновляет цены, отсутствующие позиции → «нет в наличии» (только файл; текст и ручное добавление — нет). Одно предложение магазина на карточку. История цен пишется при каждом изменении.
8. Валюта: продавец выбирает USD или UZS, цена хранится в исходной валюте; покупателю — обе по курсу ЦБ (cbu.uz, раз в день); аналитика в USD. Основная валюта отображения — UZS (оплата в Узбекистане только в национальной валюте); внутренние расчёты и аналитика — в USD. Пересчитанное помечается «≈», суммы округляются до 1 000 сум.
9. Чат — только между покупателем и магазином по товару, сборке или брони; бронь — без оплаты и доставки; карта — адрес магазина и ссылка на Яндекс Карты.

## Версии и выкладка
- Сервер = ветка `alpha` в Docker (`/opt/alt-stores`: `docker-compose.yml`, `.env`, `data/`; контейнеры `backend` и `web`, наружу только `127.0.0.1:8095`, перед ними nginx хоста). Сейчас там бета Б1–Б4, тег `v0.3-beta`. Дальнейшая разработка — в `main`; на сервер (влить `main` в `alpha` + `deploy.bat`) — только по команде Азиза. В промтах Азиза «альфа» = версия на сервере.
- `deploy.bat` работает только из ветки `alpha` и без незакоммиченных изменений: образы собираются на ПК (Docker в WSL), загружаются на сервер, копия базы, запуск, проверка. Предыдущая версия остаётся на сервере — откат `rollback.bat`. Схема базы обновляется сама при запуске (`add_missing_columns`); демо-данные на сервере — только `seed_demo.py --builds-only` (полный `seed_demo` перетасует ассортимент демо-магазинов).
- Sudo на сервере — только командами, которые вводит Азиз (`ssh -t`); остальное — через группу docker.
- Теги: `v0.1-alpha` — до Б1; `v0.2-stable` — после Б1; `v0.2.1-stable` — она же с названием ALT STORES; `v0.3-beta` — бета Б1–Б4, первая версия в Docker. Посмотреть — `git checkout <тег>`, вернуться — `git checkout main`.
- Пароли и заметки сервера — `_local\secrets\` (вне git). Копия базы сервера на ПК — ежедневно, задание Планировщика `ALT STORES server backup`, запускается из копии скриптов в `_local\tools\` (`docs/deploy.md`).

## Как запустить
- `start.bat` в корне — оба сервера + браузер на http://localhost:5173; `stop.bat` — остановить.
- `demo.bat` — демо с нуля (копия базы → чистая база → прайс из кэша → демо-магазины → архив Gshop → серверы), ≈40 с, без ИИ; `demo.bat live` — демо-файлы через живой ИИ. Кэш и курсы — `_local\samples\demo_cache.json`, кэш демо-файлов — `samples/demo/cache.json` (`scripts/demo_cache.py`). Сценарий — `docs/demo_script.md`, защита — `docs/defense.md`. Swagger: http://127.0.0.1:8000/docs.
- Вручную: `cd backend` → `.\.venv\Scripts\python.exe -m uvicorn main:app --reload`; `cd frontend` → `npm run dev`. В Claude Code — `.claude/launch.json` (`backend`, `frontend`; если 8000/5173 заняты — `backend-verify` на 8001 + `frontend-verify` на 5175).
- Тесты: `cd backend` → `.\.venv\Scripts\python.exe -m pytest` (без живых запросов к ИИ и cbu.uz); frontend — `cd frontend` → `npm test`.
- Реальный магазин «Age Computers» (полный реальный прайс; флаг `stores.is_demo = 0`, значок «Проверенный»): логин и пароль задал владелец — `scripts/set_account.py` (пароль вводится только в терминале). `demo_reset.py` и `seed_demo.py` его не сбрасывают (экспорт → восстановление). Демо-магазины: `scripts/seed_demo.py` (повторный запуск без дублей), `demo1..3@example.com` / `demo12345`; пустой магазин для живой загрузки — `live@example.com` / `demo12345`; покупатель для проверки — `buyer1@example.com` / `demo12345`. Для тестовых email — `@example.com` (`.test` отклоняется).
- Реальный прайс: `_local\samples\Price of Age Computers (9).xlsx` (вне репозитория, в git не класть).
- Docker на ПК — Docker Engine в WSL (не Docker Desktop), Ubuntu в `F:\wsl\ubuntu`; команды — `wsl docker …`, остановить — `wsl --shutdown`, место — `wsl docker system prune` (`docs/deploy.md`).
- ⚠ `--reload` перезапускает сервер при изменении любого `.py` в `backend/` — во время импорта код не править.

# Как жить без Claude — инструкция по обслуживанию ALT STORES

Для Азиза. Простыми словами, по шагам. Подробности для специалиста — `docs/deploy.md`.

**Как читать команды.** Команды `ssh pcmarket "…"` вводятся в **Git Bash** (или PowerShell) на ПК — целиком одной строкой. Файлы `*.bat` — двойной щелчок в папке `F:\claudy\diplom`. Пароль sudo вводите только вы и только когда сами решили выполнить команду с `sudo`.

---

## 1. Что где лежит

| Где | Что там | Важно |
|---|---|---|
| **ПК**, `F:\claudy\diplom` | весь код (репозиторий git), `.bat`-файлы, документы | рабочая ветка — `main`, ветка сервера — `alpha` |
| **ПК**, `F:\claudy\diplom\_local\` | то, что нельзя в git: реальные прайсы (`samples`), копии баз (`backups`), пароли сервера (`secrets`), скрипт ежедневного скачивания копии (`tools`), отчёты автопроверки (`smoke`) | синхронизируется с Google Диском; в git никогда |
| **ПК**, `backend\.env` | ключи ИИ (`GEMINI_API_KEY`, `GROQ_API_KEY`) и `JWT_SECRET` для локального сайта | в git не попадает |
| **ПК**, `backend\database.db` | база локального сайта | в git не попадает |
| **Сервер** (короткое имя `pcmarket`), папка `/opt/alt-stores` | `docker-compose.yml`, `.env` (ключи сервера), `data/database.db` (база сайта), `data/backups/` (копии), `data/media/` (фото) | сервер чужой — у Худоберди, там же его сайты и боты |
| **GitHub** | публичная копия кода (ветки `main`, `alpha`, теги `v0.3-beta`, `v1.0`) | всё, что там, видят все: никаких ключей, паролей, реальных прайсов |
| **Google Диск** | копия папки `_local` | если ПК сломается — всё самое ценное там |
| **Сайт** | https://pcmarket.khudoberdi.uz | версия `v1.0` |

## 2. Сайт на своём ПК

- **Запустить:** `start.bat` — откроется браузер на http://localhost:5173 (через 10–20 секунд).
- **Остановить:** `stop.bat`.
- **Демо с нуля** (для показа без интернета-ИИ): `demo.bat` — делает копию базы, собирает чистую демо-базу, грузит прайс из кэша, демо-магазины. ≈ 40 секунд. Сценарий показа — `docs/demo_script.md`.
- Если окно пишет, что порт занят, — сначала `stop.bat`, потом снова `start.bat`.

## 3. Выложить новую версию на сервер

Обычно это не нужно: на сервере уже финальная `v1.0`. Если всё же надо (например, исправили текст):

1. Изменения должны быть в ветке `main` и закоммичены.
2. Открыть Git Bash в `F:\claudy\diplom` и ввести по очереди:
   ```bash
   git checkout alpha
   git merge main
   ```
3. Двойной щелчок **`deploy.bat`**. Он сам: соберёт сайт на ПК, отправит его на сервер **одним SSH-подключением**, сделает копию базы, включит новую версию, проверит. В конце должно быть **`DEPLOY OK`**.
4. Сразу после — **`smoke.bat`** (см. п. 4). Должно быть **`ALL OK`**.
5. Вернуться в рабочую ветку: `git checkout main`.

- Выкладка работает **только из ветки `alpha`** и без незакоммиченных изменений — иначе откажется и ничего не изменит.
- **Если SSH не пускает** (`Connection timed out`, `Connection refused`, `Connection reset`): подождать 10 минут и попробовать снова; не помогло — **переключить ПК на мобильный интернет** (раздать с телефона) и повторить. Много попыток подряд не делать — сервер может временно заблокировать адрес.
- **Стало хуже после выкладки → `rollback.bat`.** Он вернёт прежнюю версию за несколько секунд; база не меняется. Повторный `rollback.bat` вернёт новую.

## 4. Автопроверка сайта — `smoke.bat`

- Двойной щелчок `smoke.bat`. Через ≈ 30 секунд: **`ALL OK: 10 of 10`** — всё хорошо; иначе строки **`FAIL`** с тем, что не открылось.
- Проверяет как покупатель: главная, каталог, поиск «12400f», карточка товара, б/у, сборка, «Для продавцов», страница входа, языки RU/UZ/EN, страница магазина. Ни во что не входит и ничего не меняет.
- `smoke.bat local` — то же для сайта на ПК (сначала `start.bat`).
- Отчёт сохраняется в `_local\smoke\`. Первый запуск сам установит Playwright (≈ 1 минута, нужен интернет).

## 5. Резервные копии базы

| Копия | Когда | Где | Сколько хранится |
|---|---|---|---|
| ночная на сервере | каждый день в 03:30 UTC (08:30 по Ташкенту) | сервер, `/opt/alt-stores/data/backups/*_daily.db.gz` | 14 последних |
| перед выкладкой | при каждом `deploy.bat` | там же, `*_before_deploy.db.gz` | 5 последних |
| на ПК | каждый день в 12:00 — задача Планировщика Windows **«ALT STORES server backup»** (если ПК был выключен — при следующем входе) | `F:\claudy\diplom\_local\backups\server\*.db` | 14 последних |

**Проверить, что копии свежие:**
- На ПК: открыть `_local\backups\server\` — у самого нового файла `.db` в имени должна быть вчерашняя или сегодняшняя дата. Журнал — `get_backup.log` там же (последняя строка `saved: …` — успех).
- Если сегодняшней нет — двойной щелчок `get_backup.bat` (скачает самую свежую вручную). Ошибка SSH — см. п. 3, «Если SSH не пускает».
- На сервере: `ssh pcmarket "ls -lt /opt/alt-stores/data/backups | head -5"` — сверху должна быть копия за сегодня.
- Сделать копию прямо сейчас: `ssh pcmarket "cd /opt/alt-stores && docker compose exec -T backend python scripts/backup_db.py manual 5"`.

Фото в ночную копию не входят — как их скопировать, написано в `docs/deploy.md`, раздел «Фото».

## 6. Как восстановить базу из копии

**На сервере** (если данные испортились):
1. Посмотреть копии: `ssh pcmarket "ls -lt /opt/alt-stores/data/backups"` — выбрать нужную, например `2026-11-19_0330_daily.db.gz`.
2. Одной строкой (подставить своё имя файла): остановить сайт, сохранить текущую базу как `database.db.broken`, развернуть копию, запустить:
   ```bash
   ssh pcmarket "cd /opt/alt-stores && docker compose stop backend && cp data/database.db data/database.db.broken && gunzip -c data/backups/2026-11-19_0330_daily.db.gz > data/database.db && docker compose start backend"
   ```
3. **Проверка:** через 20 секунд — `smoke.bat` (`ALL OK`), затем открыть сайт и страницу магазина Age Computers — товары на месте.
4. Если всё хорошо — через несколько дней удалить старую: `ssh pcmarket "rm /opt/alt-stores/data/database.db.broken"`. Если стало хуже — вернуть её так же: `… cp data/database.db.broken data/database.db …` (между `stop` и `start`).

**На ПК** (локальный сайт):
1. `stop.bat`.
2. Переименовать `backend\database.db` в `database.db.broken`.
3. Скопировать нужный файл из `_local\backups\server\` (или `_local\backups\`) в `backend\` и назвать `database.db`.
4. `start.bat`, проверить сайт (можно `smoke.bat local`).

## 7. Перед показом (предзащита, защита)

1. Обновить демо-сборки и данные демо-магазинов на сервере (предложения, цены и пароли не трогает):
   ```bash
   ssh pcmarket "cd /opt/alt-stores && docker compose exec -T backend python scripts/seed_demo.py --builds-only --no-photos"
   ```
   **Только с `--builds-only --no-photos`!** Полный `seed_demo.py` на сервере перетасует демо-магазины.
2. `smoke.bat` — `ALL OK`.
3. Демо-аккаунты (вход — кнопка «Вход» на сайте, адрес `/login`), пароль у всех `demo12345`:
   - демо-магазины: `demo1@example.com`, `demo2@example.com`, `demo3@example.com`;
   - пустой магазин для живой загрузки прайса: `live@example.com`;
   - покупатель: `buyer1@example.com`.
4. Реальный магазин Age Computers — пароль знает владелец магазина; в его кабинете ничего не менять.
5. Запасной вариант без интернета — `demo.bat` на ПК (п. 2). Сценарий — `docs/demo_script.md`, ответы на вопросы — `docs/defense.md`.

## 8. Как создать администратора

- **На ПК:** в папке `backend` (PowerShell):
  ```powershell
  .\.venv\Scripts\python.exe scripts\create_admin.py admin@example.com
  ```
  Пароль скрипт спросит сам (символы не видны при вводе — так и должно быть).
- **На сервере:** (`-t` — чтобы можно было ввести пароль):
  ```bash
  ssh -t pcmarket "cd /opt/alt-stores && docker compose exec backend python scripts/create_admin.py ваш-email@пример"
  ```
- Вход администратора — обычная страница `/login`, после входа — `/admin`.

## 9. Ключи ИИ (Gemini и Groq)

**Где лежат:** на ПК — `F:\claudy\diplom\backend\.env`; на сервере — `/opt/alt-stores/.env`. Строки `GEMINI_API_KEY=…` и `GROQ_API_KEY=…`. Оба — бесплатные.

**Признак, что ключ умер:** загрузка прайса или поста пишет «ИИ недоступен», в логах (`ssh pcmarket "cd /opt/alt-stores && docker compose logs --tail 100 backend"`) — `API key not valid`, `401`, `403`.

**Получить новый ключ:**
- **Gemini:** https://aistudio.google.com/apikey → войти Google-аккаунтом → «Create API key» → скопировать (начинается с `AIza`).
- **Groq:** https://console.groq.com/keys → войти → «Create API Key» → скопировать (начинается с `gsk_`).

**Заменить:**
- На ПК: открыть `backend\.env` в Блокноте, заменить значение после `=`, сохранить; `stop.bat` → `start.bat`.
- На сервере: открыть файл редактором прямо на сервере:
  ```bash
  ssh -t pcmarket "nano /opt/alt-stores/.env"
  ```
  Заменить ключ, сохранить (`Ctrl+O`, `Enter`), выйти (`Ctrl+X`). Затем применить:
  ```bash
  ssh pcmarket "cd /opt/alt-stores && docker compose up -d"
  ```
  Проверить — `smoke.bat`.
- **Ключ никогда** не вставлять в чат (в том числе с ИИ), в письма, в файлы репозитория. Если ключ случайно попал в публичное место — сразу удалить его на сайте AI Studio / Groq и создать новый.

## 10. Если ИИ не отвечает

ИИ нужен только для **новых, ещё не встречавшихся** названий товаров. Без него продолжают работать:
- весь сайт для покупателей: каталог, поиск, цены, сравнение, рынок, сборки, бронь, чат;
- цены, артикулы и наличие из прайса — их всегда берёт код, не ИИ;
- уже знакомые позиции — из кэша (повторная загрузка того же прайса проходит за секунды);
- правила: категории, Anti-Fraud, дубли.

Что делать: бесплатный лимит обычно восстанавливается через минуту (поминутный) или к следующему дню (дневной). Большой новый прайс может грузиться долго — это ожидание лимитов, не поломка. Если не отвечает несколько дней — заменить ключ (п. 9).

## 11. «Что-то сломалось» — что делать

| Симптом | Что сделать |
|---|---|
| **Сайт не открывается** совсем | 1) Проверить свой интернет на другом сайте. 2) Открыть https://pcmarket.khudoberdi.uz/api/health. Ошибка Cloudflare **521/522** — не отвечает сам сервер: написать Худоберди. **502** — не отвечает наш контейнер: `ssh pcmarket "cd /opt/alt-stores && docker compose ps"` и перезапуск `ssh pcmarket "cd /opt/alt-stores && docker compose restart"`, затем `smoke.bat`. |
| **Кабинет пишет ошибку** / «Сервер недоступен» | Перезапустить: `ssh pcmarket "cd /opt/alt-stores && docker compose restart backend"`. Не помогло — посмотреть логи `ssh pcmarket "cd /opt/alt-stores && docker compose logs --tail 100 backend"` (последние строки с `Error`). Началось после выкладки — `rollback.bat`. |
| **Прайс долго грузится** | Нормально для большого нового прайса: ИИ на бесплатном лимите (п. 10). Повторная загрузка того же файла — быстрая (кэш). Ничего не перезапускать во время загрузки. Неопубликованную загрузку можно отменить кнопкой «Отменить загрузку». |
| **Не пускает SSH** | Подождать 10 минут, повторить один раз. Не помогло — переключиться на мобильный интернет. Снова нет — написать Худоберди (может, сервер выключен). |
| **Кончилось место на диске сервера** | Посмотреть: `ssh pcmarket "df -h / && docker system df"`. Очистить только наше старьё Docker: `ssh pcmarket "docker image prune -f && docker builder prune -f"` (не трогает работающие версии и `previous`). Не удалять чужие папки и образы. |
| **После выкладки стало хуже** | `rollback.bat` → `smoke.bat`. База при откате не меняется. |
| **Данные испортились** | Восстановить из копии (п. 6). |
| **Место на ПК** (Docker в WSL разросся) | `wsl docker system prune` в PowerShell; `wsl --shutdown` — выключить WSL. |

## 12. Чего никогда не делать

- **Не трогать сайт и ботов Худоберди** на сервере: чужие папки, контейнеры, настройки nginx.
- **Не перезагружать сервер** (`reboot`) без согласия Худоберди — на нём работают его сайты.
- **Не класть ключи и пароли** в чат (с людьми и с ИИ), в репозиторий, в скриншоты. Их место — `.env` и `_local\secrets\`.
- **Не публиковать реальные прайсы** (Age Computers и другие) в git: они лежат только в `_local\samples\`. В папке `samples\` репозитория — только синтетические демо-файлы.
- Не запускать на сервере полный `seed_demo.py`, `demo_reset.py`, `find_duplicates.py --apply`, `recategorize.py --apply` — они массово меняют данные.
- Не делать `git push --force` и не удалять ветки `main` / `alpha`.

## 13. Ежемесячная проверка (5 минут)

1. ☐ `smoke.bat` → `ALL OK`.
2. ☐ В `_local\backups\server\` самый новый файл — не старше 1–2 дней.
3. ☐ `ssh pcmarket "ls -lt /opt/alt-stores/data/backups | head -3"` — сверху копия за сегодня.
4. ☐ Место на диске сервера: `ssh pcmarket "df -h /"` — в столбце `Use%` меньше 85 %. Больше — см. таблицу (п. 11).
5. ☐ Google Диск синхронизирован (значок у папки `_local` — зелёная галочка).

## 14. Как дать новую задачу ИИ-агенту в будущем

1. Открыть папку `F:\claudy\diplom` в агенте (Claude Code или другом).
2. Первая фраза: «Прочитай `CLAUDE.md`, затем нужный раздел `docs/roadmap.md` и `docs/maintenance.md`. Задача: …».
3. Правила, которые стоит повторить агенту:
   - работать в ветке `main`; на сервер — только по моей команде (влить `main` в `alpha` + `deploy.bat`, потом `smoke.bat`);
   - точечные правки, не переписывать файлы целиком; тексты интерфейса — сразу в три файла `ru.json`, `uz.json`, `en.json`;
   - перед изменением схемы базы — копия в `_local\backups\`;
   - ключи и пароли — только в `.env` и `_local`, никогда в git и не в чат;
   - сервер чужой: трогать только `/opt/alt-stores`, sudo — только моими руками, без перезагрузки;
   - после работы — все тесты, коммит, push, запись в `docs/history.md`.
4. Проверять результат самому: `start.bat` и `smoke.bat local`.

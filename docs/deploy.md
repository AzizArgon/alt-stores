# Публичная версия: https://pcmarket.khudoberdi.uz

Демо-версия дипломного проекта на арендованном сервере (VPS), чтобы куратор и знакомые открывали сайт по ссылке без ноутбука автора.
На этом же сервере работают сайты другого человека — их не трогаем: у нашего сайта своя папка, свои контейнеры Docker, своя сеть и свой файл nginx.
Адрес сервера, пароли и ключи в репозитории не хранятся: они лежат на ПК автора вне git (`F:\claudy\diplom\_local\`, папка в `.gitignore`: `_local\secrets\server_passwords.txt`, `_local\secrets\server_notes.txt`).

## Docker на ПК (для сборки образов)

Образы сайта собираются на ПК, а не на сервере (на сервере мало памяти). Docker Desktop не ставим: на ПК — **Docker Engine внутри WSL**, только командная строка.
- Ubuntu для WSL лежит на диске F: `F:\wsl\ubuntu\ext4.vhdx` (на C места мало). Пользователь `azi`, sudo без пароля только внутри WSL — это локальная песочница для сборки.
- Команды Docker — через WSL: `wsl docker ps`, `wsl docker images`, `wsl docker compose …`. Проект изнутри WSL виден как `/mnt/f/claudy/diplom`. `deploy.bat` сам вызывает Docker в WSL.
- WSL засыпает сам, когда в нём ничего не запущено, и просыпается при следующей команде. Остановить сразу: `wsl --shutdown`.
- Ограничения — `%UserProfile%\.wslconfig`: память WSL 4 ГБ, 4 ядра, swap 2 ГБ, память возвращается Windows постепенно (`autoMemoryReclaim`).
- **Освободить место:** `wsl docker system prune` (старые образы и кэш сборки). Файл диска WSL сам не уменьшается; при острой нехватке места на F — `wsl --shutdown`, затем `wsl --manage Ubuntu --set-sparse true --allow-unsafe` (Microsoft предупреждает о риске для данных — перед этим ничего ценного внутри WSL быть не должно; там только образы, их можно собрать заново).

## Как это устроено

```
Посетитель ──HTTPS──> Cloudflare ──> nginx сервера ──> 127.0.0.1:8095 ──> контейнер web (nginx) ──> /      → собранный frontend
                                                                                              └─> /api/  → контейнер backend (FastAPI)
```

- **Cloudflare** — «прокладка» перед сервером: даёт HTTPS-замок в браузере, прячет адрес сервера и передаёт настоящий IP посетителя в заголовке `CF-Connecting-IP`.
- **nginx сервера** — веб-сервер, который уже стоял на сервере. Для нашего сайта — отдельный файл `pcmarket` (порт 80 и порт 2053 с сертификатом Let's Encrypt, см. «Cloudflare и HTTPS») и общий для обоих портов кусок `snippets/pcmarket-app.conf`: он просто передаёт всё в наш контейнер на `127.0.0.1:8095`. Порт 443 на сервере занят другой программой — не используем.
- **Два контейнера Docker** (проект `alt-stores`, своя сеть):
  - `web` — маленький nginx с собранным frontend; запросы `/api/` передаёт в `backend`. Единственный, кто открыт наружу, и только на `127.0.0.1` — из интернета напрямую к нему не попасть.
  - `backend` — FastAPI. Работает от обычного пользователя, без лишних прав, файловая система только для чтения (писать можно лишь в `data/`), память — не больше 700 МБ.
  - Оба сами поднимаются после перезагрузки сервера и после падения (`restart: unless-stopped`; проверено: после остановки — снова отвечает через ≈6 с). Docker сам следит за их здоровьем (`healthcheck`).
- **Образ** — «упакованная» версия сайта: код + всё, что ему нужно. Образы собираются на ПК и привозятся на сервер готовыми, поэтому кода на сервере нет вообще.
- **База** — тот же SQLite-файл `database.db`, что и на ноутбуке, лежит рядом с контейнерами, а не внутри: смена версии сайта базу не трогает. Новые колонки добавляются сами при запуске (`add_missing_columns`). Для демо с десятками посетителей SQLite хватает.

## Что где лежит на сервере

Всё наше — в одной папке `/opt/alt-stores` (владелец — администратор сервера, другие пользователи читать не могут):

| Что | Где |
|---|---|
| Описание контейнеров | `docker-compose.yml` (копия из репозитория, привозит `deploy.bat`) |
| Настройки и ключи | `.env`, права `600` (список переменных без значений — `.env.example` в репозитории) |
| База | `data/database.db` |
| Прайсы и кэш для демо | `data/samples/` — по ссылке не открываются |
| Резервные копии базы и их журнал | `data/backups/` |
| Конфиг nginx сервера | `/etc/nginx/sites-available/pcmarket` + `/etc/nginx/snippets/pcmarket-app.conf` (шаблоны — `deploy/nginx/`) |
| Образы | `alt-stores-backend` и `alt-stores-web`, у каждого метки `current` (работает сейчас) и `previous` (для отката) |

Вход на сервер — только по SSH-ключу (`~/.ssh/id_ed25519_pcmarket`, короткое имя `pcmarket` в `~/.ssh/config`).
Всё обычное (выкладка, логи, перезапуск, копии) делается без sudo: администратор состоит в группе `docker`. Sudo нужен только для nginx и системных папок — такие команды Азиз вводит сам (`ssh -t pcmarket 'sudo …'`), пароль sudo в файлах не хранится.

## Как обновить сайт

На сервере живёт ветка `alpha`. Разработка идёт в `main`; на сервер — только по команде Азиза: влить `main` в `alpha` и запустить `deploy.bat`.

1. Перейти в ветку `alpha` с нужными изменениями, всё закоммитить (Claude делает это сам).
2. Запустить **`deploy.bat`** в корне проекта. Из другой ветки или с незакоммиченными изменениями он откажется и ничего не изменит. Иначе он сам:
   push ветки `alpha` на GitHub → сборка двух образов на ПК (Docker в WSL) → загрузка образов и `docker-compose.yml` на сервер → копия базы → прежняя версия получает метку `previous`, новая — `current`, ещё более старая удаляется → перезапуск контейнеров → проверка, что работают именно новые образы → передача курса ЦБ → проверка, что сайт и API отвечают.
3. В конце должно быть `DEPLOY OK`. Если что-то не так — `DEPLOY FAILED` с причиной. Сайт при обновлении недоступен несколько секунд.

**Откат на прежнюю версию:** `rollback.bat` — меняет местами `current` и `previous` и перезапускает контейнеры (база остаётся как есть). Повторный `rollback.bat` вернёт новую версию.

**Демо-данные на сервере** — только `seed_demo.py --builds-only` (обновляет данные демо-магазинов и демо-сборки, не трогая предложения, историю цен и пароли):
```bash
ssh pcmarket "cd /opt/alt-stores && docker compose exec -T backend python scripts/seed_demo.py --builds-only"
```
Полный `seed_demo` на сервере не запускать: он перетасует ассортимент демо-магазинов.

Cloudflare хранит `favicon.svg` до 4 часов, браузер посетителя — тоже: новый значок появляется не сразу.

Настройки публичной сборки frontend — `frontend/.env.public` (плашка «Демо-версия», адрес API `/api`); образ `web` собирается с ними.

**Курс ЦБ.** Сайт cbu.uz отвечает только узбекским адресам, а сервер за рубежом. Поэтому сервер сам курс не запрашивает (`CBU_FETCH=false`), а `deploy.bat` берёт курс на ноутбуке и передаёт на сервер. Курс обновляется при каждом deploy; между ними сайт показывает последний известный курс с его датой.

## Защита публичной версии

- **Регистрация продавцов — только по коду-приглашению** (`SELLER_INVITE_CODE` в `.env` сервера, код — в `server_passwords.txt`). Покупатели регистрируются свободно. На ноутбуке код не нужен.
- **Дневные лимиты** (чтобы посторонние не потратили бесплатную квоту ИИ): 10 загрузок прайса на магазин, 40 на весь сервер, 100 запросов к ИИ на сервер. При превышении — понятное сообщение «попробуйте завтра»; строки, на которые не хватило ИИ, можно распознать позже кнопкой «Повторить».
- **Вход:** не более 10 неудачных попыток с одного IP за 15 минут; регистраций — не более 5 в час с одного IP.
- **Настоящий IP посетителя** проходит через два nginx: nginx сервера берёт его из заголовка Cloudflare (доверяет только адресам Cloudflare) и передаёт в `X-Real-IP`, контейнер `web` передаёт его дальше, а backend верит этому заголовку только от своих (`TRUSTED_PROXIES` — сеть контейнеров). Иначе лимиты считали бы всех посетителей одним человеком.
- **Плашка** «Демо-версия дипломного проекта…» на всех страницах, в подвале — ссылка на GitHub.
- **Поисковики:** `noindex` в заголовке ответа и в `<meta>` на каждой странице + `robots.txt`. (Cloudflare на всём домене подставляет свой robots.txt с «Allow»; запрет индексации всё равно действует через `noindex`.)
- **Пароли** демо-аккаунтов на сервере заменены случайными (старые есть в публичном репозитории). Новые — в `_local\secrets\server_passwords.txt`; `--builds-only` их не трогает. Реальный магазин не трогает никакой скрипт демо-данных: его логин и пароль задал владелец (`scripts/set_account.py`, пароль — только в терминале).
- Лимиты включаются только переменными в `.env` сервера; на ноутбуке всё работает как раньше.

## Логи и перезапуск

Все команды — с ПК, без sudo:
```bash
ssh pcmarket "cd /opt/alt-stores && docker compose logs --tail 200 backend"
```
- Состояние контейнеров (должно быть `healthy`): `ssh pcmarket "cd /opt/alt-stores && docker compose ps"`.
- Перезапуск backend: `ssh pcmarket "cd /opt/alt-stores && docker compose restart backend"`; обоих — `… docker compose restart`.
- Логи `web` — `… docker compose logs --tail 200 web`. Логи хранятся не больше 2 файлов по 5 МБ на контейнер — диск не забьют.
- Запросы к сайту в nginx сервера — `/var/log/nginx/pcmarket.log`.

## Резервные копии

- Автоматически раз в день в 03:30 по времени сервера (UTC) — строка в `crontab` администратора, хранятся последние 14 (`*_daily.db.gz`). Журнал — `data/backups/backup.log`.
- Перед каждым `deploy.bat` — ещё одна копия, хранятся последние 5 (`*_before_deploy.db.gz`).
- Копия делается командой SQLite `.backup` (`scripts/backup_db.py`) — безопасно, пока сайт работает.
- **Копия на ноутбук — автоматически:** задание Планировщика Windows `ALT STORES server backup` каждый день в 12:00 запускает копию скрипта из `F:\claudy\diplom\_local\tools\` (`get_backup.bat auto` и `deploy\get_backup.sh`, вне git: задание не зависит от открытой ветки; путь к `_local` копия находит сама — это папка над `tools`; после правки `get_backup.bat` или `deploy/get_backup.sh` в `main` скопировать их туда заново); если ПК был выключен, то при следующем входе в Windows. Скачивается самая свежая копия, файлы — в `_local\backups\server\`, хранятся последние 14, журнал — `get_backup.log` там же.
- **Скачать копию вручную:** `get_backup.bat`.
- **Сделать копию прямо сейчас:** `ssh pcmarket "cd /opt/alt-stores && docker compose exec -T backend python scripts/backup_db.py manual 5"`.
- ⏰ **Напоминание: после 04.12.2026 удалить** архив старой установки (до Docker) `data/backups/2026-11-04_0632_old_pcmarket_install.tar.gz` (147 МБ: старая база, прайсы, копии и старый `.env`). Ротация его не трогает: `backup_db.py` удаляет только файлы своей метки (`*_daily.db.gz`, `*_before_deploy.db.gz` …), `get_backup` скачивает только `*.db.gz`. Удалить (без sudo): `ssh pcmarket "rm /opt/alt-stores/data/backups/2026-11-04_0632_old_pcmarket_install.tar.gz"`.

### Как восстановить базу из копии

1. Выбрать копию: `ssh pcmarket "ls -lt /opt/alt-stores/data/backups"`.
2. Остановить backend, сохранить текущую базу и развернуть копию (пример для `2026-11-03_0342_daily.db.gz`):
   ```bash
   ssh pcmarket "cd /opt/alt-stores && docker compose stop backend && cp data/database.db data/database.db.broken && gunzip -c data/backups/2026-11-03_0342_daily.db.gz > data/database.db && docker compose start backend"
   ```
3. Через несколько секунд открыть сайт. Файл `database.db.broken` удалить, когда всё проверено.

## Если сайт не открывается

1. **Проверить, что отвечает:** `curl -I https://pcmarket.khudoberdi.uz/api/health`.
   - `502 Bad Gateway` — не отвечает контейнер: `docker compose ps` и логи (выше), потом перезапуск.
   - Ошибка Cloudflare `521/522` — не отвечает сам сервер или nginx сервера: сообщить владельцу сервера.
   - Ошибка Cloudflare `525/526` — проблема с сертификатом на порту 2053 (только в режиме Full (strict)): `ssh -t pcmarket sudo certbot certificates` (сертификат `pcmarket`, продлевается сам).
2. **Сломалось после обновления** — `rollback.bat` (вернёт прежнюю версию за несколько секунд), затем разбираться с ошибкой на ПК.
3. **Сайт открывается, но «Сервер недоступен»** — не отвечает `backend`: `docker compose ps` и логи `backend`.
4. **Загрузка прайса пишет про лимит** — это защита демо-версии, сбросится завтра; лимиты меняются в `.env` сервера, затем `docker compose up -d` (перечитает `.env`).
5. Перезагрузку **всего сервера** без согласования с владельцем не делать: на нём работают другие сайты.

## Как полностью убрать сайт с сервера

Если сервер понадобится вернуть владельцу. Сначала скачать последнюю копию базы (`get_backup.bat`). Затем Азиз сам вводит (sudo):
```bash
ssh -t pcmarket 'cd /opt/alt-stores && docker compose down && docker rmi alt-stores-backend:current alt-stores-backend:previous alt-stores-web:current alt-stores-web:previous; (crontab -l | grep -v "alt-stores daily DB backup") | crontab -; sudo rm /etc/nginx/sites-enabled/pcmarket /etc/nginx/sites-available/pcmarket /etc/nginx/snippets/pcmarket-app.conf && sudo nginx -t && sudo systemctl reload nginx && sudo rm -rf /opt/alt-stores'
```
После этого проверить, что сайт друга `https://khudoberdi.uz` открывается. Сертификат `pcmarket` можно удалить командой `sudo certbot delete --cert-name pcmarket`.

## Cloudflare и HTTPS

Сейчас Cloudflare ходит к серверу по обычному HTTP на порт 80 (режим зоны Flexible) — посетитель всё равно видит HTTPS с замком.
Для режима **Full (strict)** (шифрование и между Cloudflare и сервером) всё готово на сервере (порт 2053, сертификат Let's Encrypt). Владельцу домена нужно добавить два правила — **только для поддомена**, режим всего домена не меняется:
1. *Rules → Origin Rules*: если Hostname равно `pcmarket.khudoberdi.uz` → Destination Port: `2053`.
2. *Rules → Configuration Rules*: если Hostname равно `pcmarket.khudoberdi.uz` → SSL: `Full (strict)`.

## На будущее: кабинет продавца на своём поддомене (не включено)

С фазы Б3.1 витрина и кабинет продавца — два разных интерфейса одного сайта: кабинет живёт под адресом `/seller/...`, а все ссылки между ними идут через одну настройку (`frontend/src/config/sites.js`). Сейчас настройка пустая — кабинет на том же адресе: `https://pcmarket.khudoberdi.uz/seller`. Чтобы потом вынести его на `seller.<домен>`, переделывать код не нужно:
1. **DNS.** Владелец домена в Cloudflare добавляет запись `A` (или `CNAME`) для `seller.pcmarket` (или `seller.<домен>`) на тот же сервер, с оранжевым облаком (через Cloudflare).
2. **nginx.** Ещё один блок `server` в нашем файле `pcmarket` с `server_name` поддомена и тем же `include snippets/pcmarket-app.conf` (тот же контейнер `web`); с адреса `/` поддомена — `return 302 /seller;`. Сертификат Let's Encrypt — расширить на поддомен (`certbot --expand`).
3. **Сборка.** В `frontend/.env.public` (с ним собирается образ `web`) задать `VITE_SELLER_URL=https://seller.<домен>` и `VITE_STORE_URL=https://pcmarket.khudoberdi.uz`. Ссылки «Открыть витрину», «Мой кабинет», «Для продавцов» и перенаправления после входа сами станут полными адресами (проверено тестом `frontend/src/config/sites.test.js`).
4. **Вход.** Токен входа хранится в браузере отдельно для каждого адреса, поэтому на поддомене продавец входит отдельно (вход продавца уже есть — `/seller/login`). Если нужно «один вход на оба адреса» — перенести токен в cookie на общий домен; это отдельная задача.
5. **CORS.** Если `/api` будет вызываться с поддомена на основной адрес (а не через свой `/api` поддомена) — добавить поддомен в разрешённые адреса backend.

## 1. Введение

### Актуальность
- Рынок компьютерной техники Узбекистана состоит в основном из небольших магазинов и частных продавцов; значительная часть торговли идёт через торговые центры (ЦУМ, Малика и т. п.) и Telegram-каналы **[нужен источник: обзор рынка / статистика розничной торговли]**.
- Магазины публикуют прайсы в разных форматах (Excel с объединёнными ячейками, PDF, посты Telegram со сленгом и на двух алфавитах узбекского языка); один товар записан десятками способов — это видно по реальным данным проекта (прайс Age Computers ≈2 400 строк, архив Gshop 2022 — 1 316 позиций, 5 Telegram-каналов).
- Без единого справочника товаров покупатель не может сравнить цены, а рынок непрозрачен: нет рыночной цены, истории, индексов.
- Встречаются вводящие в заблуждение предложения (серверные процессоры под видом игровых, нереальные объёмы накопителей) — нужна автоматическая проверка.
- Цифровизация торговли и прозрачность цен — направление государственной политики Узбекистана (стратегия «Цифровой Узбекистан — 2030») **[нужен источник: Указ Президента РУз о стратегии «Цифровой Узбекистан — 2030», 2020]**.
- Языковые модели (LLM) стали доступны на бесплатных тарифах, что делает автоматическую стандартизацию реальной для небольшого проекта **[нужен источник: документация Google Gemini API / Groq о бесплатных лимитах]**.

### Цель
Разработать информационную систему, которая приводит прайс-листы любых магазинов компьютерной техники к единому стандарту (эталонная карточка товара), обеспечивает честное сравнение предложений и мониторинг цен на рынке.

### Задачи (по реально сделанному)
1. Проанализировать форматы прайс-листов и постов магазинов, существующие аналоги и требования к системе.
2. Разработать конвейер разбора прайсов любого формата (Excel, CSV, PDF, текст Telegram) с распределением работы между кодом, кэшем, правилами и языковой моделью.
3. Разработать модель данных и метод сведения предложений разных магазинов в эталонную карточку (ключ сведения, словарь характеристик 31 категории, код МХИК из справочника).
4. Разработать подсистему выявления подозрительных предложений (Anti-Fraud) и мониторинга цен (рыночная цена-медиана, история, индексы категорий).
5. Реализовать веб-приложение с ролями покупателя, продавца и администратора, включая учёт остатков по филиалам, склад со сканером штрихкодов, брони и чат; интерфейс на трёх языках.
6. Оценить точность системы экспериментально на наборе с известными правильными ответами и сравнить две языковые модели (Gemini, Groq).
7. Развернуть систему на сервере (Docker) и подготовить её к эксплуатации (резервные копии, обновление, откат).

### Объект и предмет
- **Объект** — процессы торговли компьютерной техникой и публикации прайс-листов магазинами в Узбекистане.
- **Предмет** — методы и программные средства автоматической стандартизации прайс-листов и мониторинга цен с использованием правил и языковых моделей.

### Научная новизна (формулировки-заготовки)
1. Предложен многоуровневый конвейер стандартизации «код → кэш → правила → языковая модель → проверка по строке», в котором языковая модель обрабатывает только строки, не понятые правилами (на замере — треть строк), а критичные поля (цена, валюта, наличие) никогда не передаются модели.
2. Предложен принцип трёх уровней достоверности характеристик («указано продавцом», «выведено правилом», «предположение ИИ» — не сохраняется), исключающий попадание домыслов модели в карточку товара.
3. Разработан ключ сведения товаров, не зависящий от описательных слов, типа товара на трёх языках и упаковки (OEM/BOX), с сохранением определяющих характеристик.
4. Предложена двухслойная проверка предложений (правила + подсказка модели) с мягкими формулировками и механизмом оспаривания.

### Практическая значимость
- Система работает на публичном сервере с реальным прайсом магазина (Age Computers) и объявлениями из публичных Telegram-каналов.
- Магазин загружает прайс «как есть» — без переделки под формат площадки; повторная загрузка — секунды без запросов к ИИ.
- Покупатель получает сравнение всех магазинов на одной карточке, рыночную цену и предупреждения.
- Продавец получает учёт остатков, склад со сканером, брони и чат без отдельной программы учёта.
- Затраты на ИИ — ноль (бесплатные лимиты).

## 2. Глава 1 — обзор и требования

### Обзор аналогов (только общеизвестное; цифры не приводить без источника)
| Аналог | Что это | Чем отличается от ALT STORES |
|---|---|---|
| **Uzum Market** | маркетплейс Узбекистана: продаёт сам, продавец заводит карточки в формате площадки | не принимает прайс «как есть»; нет сравнения одного товара у разных магазинов как цели; нет учёта для магазина |
| **OLX.uz** | доска объявлений | нет стандартизации: один товар — много разных объявлений; нет рыночной цены |
| **Olcha.uz, Texnomart, Mediapark** | интернет-магазины / сети электроники | продают свой ассортимент, не агрегируют чужие предложения |
| **Oson Apteka** (Узбекистан) | поиск лекарств по аптекам: один препарат — все аптеки | ближайший аналог по модели «эталон + предложения»; другая отрасль |
| **Яндекс Маркет, Hotline.ua, Kaspi.kz** (другие страны) | агрегаторы цен / маркетплейсы с карточками товаров | работают с крупными магазинами по фидам (YML и т. п.); не разбирают «грязные» прайсы и посты; не работают в Узбекистане как агрегатор местных магазинов **[проверить по источнику]** |
| **PCPartPicker** (США) | подбор комплектующих и сравнение цен | только крупные магазины по API; сосредоточен на совместимости |
| **1С, «МойСклад»** | учёт и склад | нет витрины для покупателя и сравнения рынка; ALT STORES не заменяет бухгалтерию |

Вывод для главы: ни один из аналогов не сочетает (1) приём прайса в любом формате, (2) стандартизацию в эталонную карточку, (3) проверку подозрительных предложений и (4) учёт для небольшого магазина в условиях Узбекистана (сумы/доллары, узбекский язык, Telegram).

### Требования к системе
**Функциональные:**
- загрузка прайса (xlsx, xls, csv, pdf), вставка текста поста, добавление из каталога; предпросмотр с правкой; публикация; отмена последней загрузки (7 дней);
- стандартизация: категория (31), бренд, модель, характеристики по словарю, код МХИК из справочника, ключ сведения;
- Anti-Fraud: правила + подсказка ИИ, уровни info/warning/danger, оспаривание;
- каталог: поиск, фильтры по характеристикам, город; карточка с предложениями всех магазинов, сортировка «рекомендованные / дешевле»; б/у отдельно; готовые сборки;
- мониторинг: рыночная цена (медиана), история, индексы категорий, аналитика продавца;
- учёт: режимы «Только прайс» / «Учёт остатков», филиалы, склад, журнал движений, штрихкоды, ревизия, импорт/экспорт Excel;
- брони без оплаты, чат по теме, уведомления; админка (магазины, жалобы, флаги, исправления, фото, штрихкоды, Telegram-каналы, журнал);
- три языка интерфейса (ru, uz латиница, en).

**Нефункциональные:**
- цена, валюта и наличие не зависят от ИИ; ИИ — только на бесплатных лимитах;
- адаптивность: телефон от 360 px, планшет, ПК;
- безопасность: хэш паролей bcrypt, JWT, проверка ролей на сервере, лимит попыток входа, минимум личных данных;
- надёжность: ежедневные копии базы, обновление с копией и откатом;
- разбор повторного прайса — секунды (кэш).

**Не делаем (границы проекта):** доставка, оплата, касса, фискальные чеки, налоги, перемещения между филиалами, сотрудники филиалов, интеграция с 1С, отчёты по выручке, коды МХИК для чеков, поставщики, продажа от имени площадки, конструктор ПК.

### Выбор технологий с обоснованием
| Технология | Почему выбрана | Альтернативы |
|---|---|---|
| Python + FastAPI | удобная работа с таблицами и ИИ, автоматическая документация API (Swagger), асинхронность для запросов к ИИ | Django (тяжелее), Node.js |
| SQLAlchemy + SQLite | база в одном файле, без отдельного сервера; переход на PostgreSQL — смена строки подключения | PostgreSQL сразу (избыточно для одного сервера) |
| React + Vite + Tailwind CSS | самый распространённый способ делать интерактивный интерфейс; быстрая сборка; оформление без отдельных CSS-файлов | Vue, серверные шаблоны |
| react-i18next | все тексты в файлах перевода, три языка без правки кода | ручные словари |
| markitdown, pdfplumber | один вход «файл → таблица» для всех форматов | отдельный код под каждый формат |
| Google Gemini (основной), Groq (запасной) | бесплатные лимиты, строгий JSON-ответ, разные провайдеры страхуют друг друга | OpenAI (платно), своя модель (нужны данные и мощности) |
| Pillow | проверка и стандартизация фото | внешние сервисы |
| Docker + nginx + Cloudflare | одинаковая среда на ПК и сервере, простая выкладка и откат, HTTPS | ручная установка на сервер |
| JWT + bcrypt | стандарт для веб-авторизации без хранения сессий | сессии на сервере |

## 4. Перспективы развития
Всё, что сознательно вынесено за рамки проекта или не успело к заморозке функций (18.11.2026):

**Торговля и учёт**
- интеграция с 1С и «МойСклад»; подключение к кассовым системам (продажи приходят автоматически);
- учётные записи сотрудников филиалов; перемещения между филиалами; несколько складов;
- отчёты по выручке и прибыли; раздел поставщиков; «под заказ» для товаров со склада;
- доставка и оплата на сайте (требуют лицензий и логистики); заказ у нескольких магазинов с доставкой.

**Данные и ИИ**
- распознавание цены на картинке поста (OCR);
- справочник моделей процессоров как третий источник характеристик;
- третий ИИ-провайдер для сравнения (например, DeepSeek через OpenRouter);
- более точный ключ для мониторов (слова «ProArt», «Curved», «PLUS»);
- подсказка продавцу при сильном отклонении его цены от рынка.

**Фото**
- удаление фона, ИИ-увеличение маленьких фото (апскейл);
- официальные фото по договорам с дистрибьюторами, своя фотостудия;
- облачное хранилище S3 (Cloudflare R2 / Backblaze B2 — интерфейс хранения уже готов);
- «Сфотографировать с телефона» по QR-коду с одноразовой ссылкой.

**Интерфейс и связь**
- тёмная тема; мобильное приложение (API уже есть);
- внешние уведомления: Telegram-бот, SMS, почта;
- вход через Google / OneID (кнопки «скоро» уже есть на странице входа).

**Инфраструктура**
- PostgreSQL и очередь задач для тысяч магазинов;
- режим шифрования Cloudflare «Full (strict)»;
- автоматическая проверка интерфейса (Playwright) при каждой выкладке.
